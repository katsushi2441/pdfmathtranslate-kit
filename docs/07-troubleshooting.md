# 07 トラブルシューティング

当社が実際に踏んだものだけを載せています。

| 症状 | 原因 | 対処 |
|---|---|---|
| `ImportError: cannot import name 'TextTranslateRequest'` で起動しない | 依存の `tencentcloud-sdk-python-tmt` が新しすぎる（3.1.129でクラス名が変更） | `pip install "tencentcloud-sdk-python-tmt==3.1.121"` |
| 翻訳が全部終わった後に `FileNotFoundError: ...-mono.pdf` | `-o` で指定したディレクトリが存在しない。pdf2zh は作らない | 実行前に `mkdir -p out` |
| 訳文が中国語になる | `-lo` の既定が中国語 | `-lo ja` を必ず付ける |
| 1ページに1分以上かかる | 思考型モデルが隠れた推論を生成している | `scripts/patch_ollama_think.py` を当てる（当社実測で81秒→14秒） |
| 訳文が空・一部のページだけ英語のまま | 翻訳エンジンの応答が空。思考型モデルか、モデルの出力上限 | 上と同じ。直らなければ `-t 1` で並列を落として再実行 |
| `-p 3` にしたのに1〜3ページが訳されない | `-p` は「そのページだけ」の指定 | 範囲で指定したいときは `-p 1,2,3` |
| 数式が翻訳されて壊れる | 数式領域の判定漏れ | `-f` に数式フォント名の正規表現を追加 |
| 本文が数式と判定されて訳されない | 上の逆 | `-f` の指定を緩める |
| スキャンしたPDFで何も訳されない | 文字層が無い（画像だけ） | `pdftotext doc.pdf -` で確認。空ならOCRを先に |
| GUIにPDFを上げると413エラー | nginx の `client_max_body_size` が既定1MB | 100M 等に変更 |
| GUIが途中で切れる | `proxy_read_timeout` が短い | 1800 秒程度に延ばす |
| 初回実行が異様に遅い／外に出られない環境で止まる | モデルと日本語フォントを自動ダウンロードしている | 外に出られる環境で1度実行し、`~/.cache/babeldoc/` を持ち込む |
| ディスクが足りなくなる | 導入で約1.3GB、キャッシュで約1GB、対訳PDFは元の1.5〜2倍 | 事前に5GB程度の空きを確保 |
| 翻訳が遅い・GPUが競合する | 並列数が多すぎる／他のAI処理と取り合っている | `-t` を下げる。一括処理は直列にする |

## 切り分けの順番

1. `pdf2zh --version` が通るか（通らなければ依存の問題）
2. `-s google -p 1` で1ページだけ訳せるか（通れば本体は正常。翻訳エンジンの設定の問題）
3. 翻訳エンジンに直接つながるか（Ollama なら `curl $OLLAMA_HOST/api/tags`）
4. `pdftotext` で原文から文字が取れるか（取れなければスキャンPDF）
