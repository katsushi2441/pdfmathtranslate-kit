# 03 ローカルLLMで翻訳する（推奨構成）

社内サーバーのGPUで翻訳します。文書は社外に出ず、翻訳は何ページ処理しても無料です。

## 1. Ollama を用意する

翻訳用のLLMを動かすサーバーを1台用意します（既にあるならそれを使います）。

```bash
# 翻訳サーバー側
curl -fsSL https://ollama.com/install.sh | sh
ollama pull gemma3:12b      # 例。日本語の品質が実用水準のモデルを選ぶ
```

外部から使う場合は `OLLAMA_HOST=0.0.0.0` で待ち受けます。**社内ネットワークの中だけに開いてください**（Ollama に認証はありません）。

## 2. pdf2zh から接続する

```bash
export OLLAMA_HOST="http://192.168.0.10:11434"   # 翻訳サーバーのアドレス
export OLLAMA_MODEL="gemma3:12b"
mkdir -p out
pdf2zh doc.pdf -li en -lo ja -s ollama -t 4 -o out
```

`-t` は並列数です。GPUが1枚なら 4 前後が目安で、増やしすぎると待ち行列ができて逆に遅くなります。

## 3. 思考型モデルを使うなら必ず読む（当社実測で5.8倍の差）

最近のモデル（gemma4 系など）は「思考型」で、答える前に内部で長い推論を書きます。**pdf2zh はこれを止める指定を送っていません**。その結果、見えない推論トークンが生成され、翻訳が遅くなります。空の応答が返って訳文が抜けることもあります。

当社の実測（同一ページ・同一モデル・GPU1枚）:

| 設定 | 1ページの所要 |
|---|---|
| 既定のまま（思考が有効） | **81秒** |
| 思考を止める（`think=False`） | **14秒** |

訳文の品質は同等でした（日本語の文字数は 39,014 と 39,006 でほぼ一致、訳語の選択も同水準）。**速度だけが5.8倍**変わります。

### 対処

同梱の `scripts/patch_ollama_think.py` を実行すると、pdf2zh の Ollama 接続部分に `think=False` を追加します。

```bash
python3 scripts/patch_ollama_think.py .venv/lib/python3.10/site-packages/pdf2zh/translator.py
# → patched: ... (backup: .bak)
```

`.bak` が残るので、pdf2zh を更新したら当て直してください（更新で上書きされます）。思考型でないモデルを使う場合は不要です。

## 4. 実測の目安

当社の測定（英語の学術論文15ページ・数式と表つき・GPU1枚・並列4・思考を止めた状態）:

| 項目 | 実測 |
|---|---|
| 全15ページ | **179秒**（約3分） |
| 1ページあたり | 11秒 |
| 翻訳された日本語 | 9,783文字 |
| 費用 | 0円 |

ページごとの所要は 4〜17秒とばらつきます。文字の多いページほど遅くなり、図表だけのページは数秒で終わります。

## 5. 品質を上げる小さな工夫

- **モデルは大きいほど固有名詞に強い**。12B前後が速度と品質の折り合いです。
- **温度は0**が既定です（pdf2zh 側で設定済み）。翻訳では上げないでください。数式の目印が壊れます。
- 訳語を統一したい場合は用語集を使います（`05-operation-design.md`）。
