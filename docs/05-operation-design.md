# 05 実務の設計

## 翻訳対象の棚卸し

まず何を翻訳するかを決めます。`templates/01-翻訳対象の棚卸し表.md` に、文書の種類・件数・機密区分・翻訳エンジンの割り当てを書き出してください。**機密区分によってエンジンが変わる**ので、この表が設定の根拠になります。

## 用語集で訳語を統一する

同じ製品名が「トランス」「変圧器」「Transformer」と揺れると、読み手が混乱します。実務では次の2段構えにします。

1. **翻訳させない語を除外する**（`-f` の正規表現。型番・製品名・社名）
2. **訳語を決めておく**（`templates/03-用語集.md`）。ローカルLLMを使う場合、プロンプトに用語集を差し込む運用ができます

`pdf2zh` はカスタムプロンプトに対応しています（Ollama・OpenAI 等のLLM系エンジンのみ）。用語集を渡す例は `scripts/translate_with_glossary.sh` を参照してください。

## 一括処理

フォルダの中のPDFをまとめて翻訳します。同梱の `scripts/batch_translate.sh` は次を行います。

- 出力先ディレクトリを先に作る（作らないと最後に落ちます）
- 1本ずつ直列で処理する（並列にするとGPUを取り合って全体が遅くなります）
- すでに訳したファイルは飛ばす
- 1本ごとに所要秒数と結果をログに残す

```bash
bash scripts/batch_translate.sh ./input ./output
```

## 品質チェック

翻訳した結果を人が全部読むのは現実的ではないので、機械で通るものは機械で見ます。同梱の `scripts/check_quality.py` は、翻訳後のPDFについて次を出します。

- ページごとの日本語文字数（**0のページは翻訳が抜けている**）
- 原文と訳文のページ数の一致
- 数式・引用番号が残っているか

```bash
python3 scripts/check_quality.py output/doc-mono.pdf --source input/doc.pdf
```

当社の実測例（15ページの論文）では、日本語文字数はページごとに 53〜1,475 文字でした。**参考文献と図版のページは少なくなるのが正常**です。0が続く場合は翻訳エンジンの接続を疑ってください。

チェック結果は `templates/04-品質チェック表.md` に記録します。

## 費用の管理

- ローカルLLM・Argos: 0円（電気代のみ）
- クラウドAPI: 文字数課金。翻訳対象は本文のみなので、`pdftotext doc.pdf - | wc -m` のおよそ7〜8割が目安です

月にどれだけ翻訳するかが読めない段階では、**まずローカルで回して実績を取る**ことをおすすめします。当社は15ページ3分・0円で回しています。
